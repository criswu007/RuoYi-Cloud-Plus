# ruoyi-address 模块规则

## 查询与性能
- 查询语义先看前端交互：列表接口返回分页结果，候选搜索返回受限结果，下拉接口返回列表结果；不要按“大表/小表”机械区分查询方式。
- 对高数据量、高频链路，主查询仍需严格控制扫描范围；列表、分页、搜索主查询禁止无必要的自关联或跨事实表 join。
- 列表、分页、搜索只查当前页必需字段；父级名称、层级、展示型衍生字段统一在服务层批量补齐。
- 禁止列表结果逐条回查详情或字典形成 N+1；必须批量查询后一次性回填。

## 分页与跨库兼容
- 分页与否由前端交互决定：常规列表走 `PageQuery.build()`，候选搜索走 `new Page<>(1, limit, false)`，下拉类接口直接返回列表并在服务层按交互约束截断结果。
- XML 中禁止使用数据库方言片段：`ifnull`、`limit`、`concat('%', ...)`、`now()`。
- 详情按主键唯一条件查询，不写 `limit 1`。

## SQL 设计约束
- `ADDR_SEGM.segm_type` / `segm_addr_type.addr_type_id` 是地址级别判定的统一事实来源；不要再混用旧 `level_id=1/2` 语义推断一二级地址。
- 前后端“1-19 级地址”统一使用 `addrLevel` 字段；`levelId` 只保留给数据库真实 `segm_addr_type.level_id`。
- 涉及当前用户区域过滤时，先在服务层收敛 `regionId`，再下推到主查询条件。
- 需要排序但又不能依赖数据库私有函数时，优先使用标准 SQL（如 `case when`、`coalesce`）。

## 变更交付
- 变更核心查询链路时，优先补充/更新针对性能约束和跨库兼容的测试。
- 若本次改动涉及 `ruoyi-address-ui` 前端代码，改完后必须重启前端项目。
