# 标准地址服务从 0 到 1 开发计划

## 目标与边界
- 需求基线：以 `/Users/criswu/Desktop/广电/需求/技术需求书_标准地址_待明确问题0323.docx` 及其备注为准。
- 服务形态：独立微服务。
- 地址层级：标准地址维护 19 级；选址平台仅到第 11 级（建筑、楼栋）。
- 本期包含：非标地址监控与外部系统对接（工单系统对接但不实现工单系统本身）。
- 新旧系统关系：暂不明确，需兼容性预案。
- 一二级标准地址：外部预置只读，不允许新增、修改、删除、合并、拆分。
- 标准地址查询口径：`1/2` 级行政区划优先按 `spec_region` 处理，其余层级按 `segm_addr` / 标准地址事实表处理；层级排序以 `segm_addr_type.level_id` 为准。
- 标准地址字段口径：`城区/非城区` 复用 `addr_segm.is_city`，`area_type` 表示城乡属性，两者需分开建模。
- 安装地址口径：正常业务流程下默认必须关联标准地址；未关联安装地址仅保留给历史迁移和异常治理场景。

## 里程碑与交付物
### M1 需求冻结与模型定稿
- 交付物：需求范围清单、地址层级定义、字段字典、唯一性与拼装规则、权限与数据范围规则。
- 关键动作：明确层级名称与编码规则；确认 `spec_region/segm_addr/segm_addr_type` 的查询与层级口径。

### M2 核心数据能力
- 交付物：标准地址 CRUD、批量新增/导入、导出、操作日志。
- 关键动作：拼装名称/简拼自动生成与级联刷新规则；简拼按“中文转拼音首字母大写、中文括号转英文括号、数字不变”生成；删除约束与二次确认逻辑；批量新增父级搜索复用与 `200` 条限制；导出“本页 / 选中 / 选字段”三种模式落地。

### M3 关联与扩展能力
- 交付物：安装地址关联、标签/属性扩展、管理站关联。
- 关键动作：标准地址变更同步到安装地址与下级地址的规则落地；安装地址默认关联标准地址并补齐双向同步链路；管理站按 `spc_station + region_id` 初始化，并依据 `MANAGE_TYPE` 字典在关系层补齐 `维修/安装/营业` 三类角色。

### M4 合并/拆分与治理
- 交付物：合并与拆分流程、校验规则、回滚策略。
- 关键动作：处理层级变化与数据一致性、审计记录；补齐“同级禁止合并”“低等级不能作为目标地址”“源地址默认回收删除”“重名预警”等规则。

### M5 非标地址监控
- 交付物：监控规则配置、定时任务、异常记录、告警/工单对接。
- 关键动作：监控规则清单与检测规则引擎固化。

### M6 外部系统对接
- 交付物：BOSS/工单/企业微信/大数据/地图对接接口。
- 关键动作：同步策略、幂等、异常重试与补偿策略；补齐标准地址查询给工单系统、选址能力给 BOSS/企业微信、数据库查询能力给大数据平台的边界。

### M6.5 网格与外围联动
- 交付物：网格组织、网格、网格地址、网格客户、网格经理及其对外同步能力。
- 关键动作：仅允许在广电站节点下新增网格；删除组织先校验子节点；删除网格同时校验地址划分与手工划分两类客户来源；网格客户默认仅展示手工划分数据。

### M7 验收与上线
- 交付物：验收用例、数据回放脚本、上线清单、回滚方案。

## 风险与预案
- 新旧系统并行未定：预留全量导入与增量同步接口。
- GIS 对接不确定：提供可插拔适配层，不阻塞主流程。
- 管理站、城乡属性等历史字段质量不稳定：保留历史兼容字段并增加字典映射与治理脚本。
- 需求书中的 `spec_region` 与历史盘点中的 `spc_region` 命名存在差异：实现前需核对联调库实际表名，避免把行政区划和区域主数据接错。
- 数据量大：所有批量操作默认分页与异步化预案。

## 开发顺序建议
1. 先落地标准地址核心 CRUD 与层级规则。
2. 同步推进导入/导出、日志审计和管理站/属性扩展。
3. 再做合并/拆分、安装地址默认关联与选址生成链路。
4. 补齐网格组织、网格划分和客户覆盖优先级。
5. 最后接入监控与外部系统。
