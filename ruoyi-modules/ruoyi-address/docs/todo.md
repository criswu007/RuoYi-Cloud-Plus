### TODO-2026-04-03-01 标准地址名称模糊查询偶发数据库通讯异常

- 发现日期：`2026-04-03`
- 当前状态：`待处理`
- 优先级：`高`
- 现象：
  - 标准地址写链路成功后，紧接着调用 `/address/standard/list` 并带 `segmName` 模糊条件时，接口偶发返回 `500`。
  - 错误核心为 `Communications link failure`。
- 影响范围：
  - 影响标准地址列表页按名称模糊检索。
  - 影响联调阶段“新增后立即按名称回查”的验证路径。
- 复现线索：
  - 典型 SQL 为 `ADDR_SEGM` 上带 `a.segm_name like ?`、`a.region_id = ?`、`order by a.create_date desc` 的分页查询。
  - 错误出现时，报文中显示最近一次成功收包与发包间隔约 `10s`。
- 已知事实：
  - 不带模糊条件的最新列表查询稳定可用。
  - 标准地址详情、合并、拆分、标签、管理站、安装地址等接口本轮联调均可正常完成。
  - 当前尚未确认根因是：
    - 线上库网络瞬时抖动；
    - 连接池保活 / 超时配置不足；
    - 模糊查询扫描范围偏大导致连接超时；
    - 以上因素叠加。
- 临时规避：
  - 联调时优先使用“最新列表 + 详情 + 操作日志”组合校验写链路结果，避免依赖新增后立即模糊回查。
- 下一步建议：
  - 补抓后端 SQL 耗时、Druid 连接池状态与数据库侧慢 SQL / 连接日志。
  - 复核 `ADDR_SEGM` 相关名称检索索引、排序字段与连接池超时参数。
  - 必要时增加更稳定的“按精确主键 / 最近创建记录”联调辅助查询路径。
